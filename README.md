# LOOPFORM: анимированный лендинг-презентация

Демо-бизнес LOOPFORM печатает дизайнерскую мебель на 3D-принтере из переработанного пластика Казахстана. Сквозная идея сайта: при прокрутке стул печатается слой за слоем.

Изображения, 3D-модели и демо-данные созданы для учебного проекта. Telegram-бот `loopform_bot` вымышленный: кнопка «Отправить заявку» формирует настоящую ссылку, но бота не существует.

## Запуск

```bash
npm install
npm run dev
npm run build
npm run preview
```

| Команда | Что делает |
| --- | --- |
| `npm run build` | проверяет типы через `tsc -b` и собирает проект |
| `npm run shoot` | снимает скриншоты всей страницы в `shots/` на 1440×900 и 390×844 |
| `npm run verify` | проверяет поведение: печать, разлёт букв, коллекцию, форму, презентацию, адаптив |
| `npm run fps` | измеряет частоту кадров на настоящей видеокарте |
| `npm run gestures` | снимает реакцию на палец: крышки, поворот, щипок, нажатие на шар |
| `npm run compare` | рендерит каждую 3D-модель в ракурсе её фото и кладёт рядом со снимком в `shots/models/compare.png` |

Скрипты работают с собранной версией, поэтому перед ними нужен `npm run build`. Для всех трёх команд нужен установленный Chrome и видеокарта: при программном рендере кадры идут слишком редко, и проверки с ожиданием срабатывают неверно.

Служебные режимы:

- `?test=print` открывает тестовую сцену с ползунком `uProgress` и всеми моделями.
- `?debug` показывает панель fps, маркеры ScrollTrigger и рамки якорей.
- `?shoot` открывает `window.__lenis` в собранной версии для скриптов.

## Архитектура скролла

### Lenis, ScrollTrigger и three.js

Цепочка данных идёт в одну сторону:

1. Lenis создаёт инерционный скролл. Один экземпляр живёт в `animation/lenis.ts`.
2. `gsap.ticker` вызывает `lenis.raf`, поэтому скролл и анимации считаются в одном цикле кадров. `lagSmoothing(0)` запрещает GSAP растягивать время после паузы, иначе анимации разойдутся со скроллом.
3. Событие `scroll` у Lenis вызывает `ScrollTrigger.update`.
4. Хук `useSectionProgress` создаёт ScrollTrigger на каждый отрезок из `segments` в `animation/tokens.ts` и пишет значение 0..1 в объект `progress`.
5. Компонент `Director` в каждом кадре читает `progress`, вызывает `runChoreography` и записывает цели для всех 3D-объектов.
6. Актёры плавно тянутся к целям через `MathUtils.damp`.

Объект `progress` намеренно не реактивный. Если бы он лежал в обычном состоянии zustand, React перерисовывал бы секции на каждом кадре скролла. Реактивными остались только редкие события: активная модель, тема шапки, режим презентации.

### Стопка секций

В проекте нет GSAP pin. Закрепление делает CSS `position: sticky` внутри компонента `StackSection`. Секция лежит в обёртке с заданной высотой, а следующая секция получает `margin-top: -100vh` и более высокий `z-index`. Поэтому она наезжает на закреплённую секцию снизу.

Sticky выбран, потому что pin добавляет отступы и пересчитывает позиции. При десятках триггеров и наложении секций это даёт скачки. Sticky держит браузер, а ScrollTrigger только считает прогресс.

Интро устроено иначе: это обычный блок с `margin-bottom: -100vh`, который лежит поверх героя и уезжает вверх.

Высоты обёрток лежат в `sectionHeights`, а все ключевые точки лежат в `segments`, в единицах vh от момента, когда верх секции доходит до верха экрана.

| Секция | Верх секции, vh | Что происходит |
| --- | --- | --- |
| Интро и герой | 0 | интро уезжает на 0–100, стул печатается на 40–200, буквы разлетаются на 110–190 |
| Коллекция | 200 | наезжает на 100–200, четыре модели на 200–600 |
| Каталог | 700 | наезжает на 600–700 |
| Проблема | 830 | падение на 830–900, куча на 900, силуэт на 900–960 |
| Процесс | 1380 | наезжает на 1280–1380, горизонтальная лента на 1380–1580 |
| Паспорт | 1680 | наезжает на 1580–1680, морфинг на 1680–1810 |
| Конфигуратор | 1880 | наезжает на 1780–1880, закреплён на один экран |
| Манифест | 2080 | фото проявляется на 2080–2160 |
| Для бизнеса | 2230 | наезжает на 2130–2230 |
| Рынок | 2330 | обычный поток |
| FAQ, CTA, футер | 2430 | обычный поток, физика в конце |

### Один холст поверх страницы

`three/Stage.tsx` держит один `Canvas`: фиксированный, на весь экран, с `z-index: 20`, прозрачным фоном и `pointer-events: none`. Заголовки лежат ниже холста, поэтому 3D проходит поверх них. Шапка, мини-карточка и значок лежат выше холста.

Клики проходят сквозь холст к DOM. Курсор сцена получает через `eventSource` на корневом элементе.

На время интро холст обрезается через `clip-path`. Его видимая часть начинается от нижнего края тёмной панели, поэтому стул появляется из-под неё, а не висит поверх.

### Якоря

В DOM лежат невидимые блоки с атрибутом `data-anchor`. Модуль `three/anchors.ts` переводит их прямоугольник в мировые координаты на плоскости z = 0. При fov 28 и расстоянии 12 высота видимой области равна примерно 5,98 единицы, поэтому пересчёт сводится к одному множителю. Вёрстка решает, где стоит 3D, а сцена только подстраивается. Это работает на любом экране.

Вариант `stuck` читает положение якоря так, как будто секция уже закреплена. Благодаря этому стул на стыке героя и коллекции интерполируется между двумя неподвижными точками: на 150vh край коллекции проходит ровно через его центр.

## Материал печати

`three/materials/printMaterial.ts` расширяет `MeshStandardMaterial` через `onBeforeCompile`. GLSL лежит в отдельных файлах и подключается через `?raw`.

Как считается печать:

- `printVertexMain.glsl` передаёт во фрагментный шейдер позицию в координатах объекта `vObjPos`. Здесь же работает морф ножек: всё ниже сиденья растягивается на `uLegStretch`.
- `printClip.glsl` считает `cutY = mix(uMinY, uMaxY, uProgress)` и отбрасывает всё, что выше этой высоты.
- `printColor.glsl` затемняет цвет синусом высоты, поэтому видны валики. Здесь же рисуется терраццо: пространство режется на ячейки, хэш решает, есть ли в ячейке хлопье, а расстояние до центра ячейки делает хлопье круглым.
- Задние грани окрашены в тёмный цвет с примесью оранжевого. Срез выглядит заполненным расплавом, а не пустой оболочкой.
- `printNormal.glsl` наклоняет нормаль производной синуса, и валики ловят свет.
- `printRoughness.glsl` меняет шероховатость по той же волне.
- `printEmissive.glsl` зажигает полосу у линии среза. Это светящаяся линия сопла.

Отдельный `MeshDepthMaterial` повторяет отсечение, иначе тень падала бы от целого стула.

`uLayerHeight` по умолчанию равен 0,0016, но при рендере ограничен снизу так, чтобы один слой занимал не меньше 4 пикселей. Настоящие слои 1,6 мм на экране мельче пикселя и дают муар.

Сопло живёт в `PrintNozzle.tsx`: светящийся диск и 32 искры ходят по контуру сечения на высоте среза того актёра, который сейчас печатается.

### Витки и совпадение с фото

Витки считаются не от высоты, а от атрибута вершины `aLayer`. Это длина пути вдоль формы: у стула вдоль изгиба спинки и сиденья, у кресла по кромке, у тел вращения по профилю. Поэтому витки огибают форму, а на крышке TAS сходятся в кольца. Шейдер рисует круглый виток: `layerRod` даёт профиль полукруга, нормаль наклоняется по градиенту `aLayer`, а щели темнеют в сторону насыщенного цвета изделия. На мелком масштабе рельеф плавно исчезает, чтобы не было муара.

Высота витка, цвет, вид крапин и ракурс витрины заданы для каждой модели в `modelLibrary.ts`. Профили TAS, SAULE, JAPYRAQ и KOL сняты с силуэтов на фотографиях. Столешница KOL использует режим дерева (`uGrain`), подушка отдельный войлочный материал. Свет SAULE сделан без прозрачности: `uGlow` добавляет свечение там, где поверхность смотрит на камеру, поэтому лампа дешевле старой версии с `transmission`.

## Актёры

Актёр в `Actor.tsx` это группа с моделью и своим экземпляром материала. Всего их восемь: `tolqyn`, `tas`, `qum`, `saule`, `stool`, `processPrint`, `processFinal`, `configChair`. Геометрия у актёров общая, материал свой, потому что у каждого свой `uProgress`.

Высота и прогресс каждого кадра приходят из `choreography.ts`. Это чистая функция по смыслу: на входе размер экрана и прогресс секций, на выходе цели для актёров, частиц и сопла.

Положение тянется к цели с коэффициентом 6. Объекты, привязанные к движущимся стыкам, используют большую жёсткость, чтобы не отставать от границы секции.

## Система частиц

`ParticleField.tsx` держит два `InstancedMesh`: 240 крышек и 360 хлопьев на компьютере, 70 и 100 на телефоне. Все матрицы обновляются в одном цикле `useFrame`.

`particleStates.ts` описывает состояния. Функция `sampleState` возвращает положение и масштаб частицы в заданном состоянии. Каждый кадр частица считается в двух состояниях и смешивается между ними с индивидуальной задержкой.

| Состояние | Поведение |
| --- | --- |
| `cloud` | облако вокруг модели, медленное вращение, отталкивание от курсора в радиусе 0,8 |
| `intake` | точка сопла с масштабом 0 |
| `fall` | старт над экраном |
| `heap` | куча у нижнего края |
| `silhouette` | точки на поверхности стула из `MeshSurfaceSampler` |
| `morph` | путь от точки на поверхности стула к точке на поверхности табурета |
| `hidden` | масштаб 0 в текущем месте |

Цвет меняется отдельно: при смене модели 62% частиц перетекают в её цвет за 0,8 с, остальные остаются цветами палитры.

**Реакция на палец и курсор.** `pointerField.ts` собирает положение и скорость мыши и касаний. Касания читаются через `touchmove`, потому что `pointermove` прерывается, как только браузер начинает прокрутку. У каждой частицы есть своё смещение и скорость: палец отталкивает её и тянет за собой, а пружина возвращает на место. Поэтому за пальцем остаётся коридор, который плавно затягивается. На сценах с крышками стоит `touch-action: pan-y pinch-zoom`: горизонтальное движение пальца не отдаётся браузеру, а вертикальное по-прежнему листает страницу.

`LabelShards.tsx` рисует 8 изогнутых обрывков этикеток в герое. `ProcessIllustrations.tsx` рисует иллюстрации шагов процесса: крышки в боксе, четыре цветные кучки, вихрь хлопьев и QR-бирку. QR собирается из ссылки библиотекой `qrcode-generator`.

## Анимации по секциям

**Прелоадер.** Логотип открывается снизу вверх через `clip-path` в 12 дискретных шагов. Счётчик слоя показывает минимум из реальной загрузки и времени, поэтому эффект виден не меньше 1,6 с. Реальная загрузка складывается из шрифтов, готовности холста и `useProgress`. Уход: 8 полос разъезжаются влево и вправо с интервалом 0,05 с.

**Интро.** Строки выезжают из масок после прелоадера. При скролле текст движется быстрее панели, а строки уходят в свои маски.

**Герой.** `FitText` подбирает размер так, чтобы самая длинная строка заняла 92vw. Вход запускается, когда панель интро начинает уезжать: иначе он прошёл бы под панелью незаметно. Стул на 0–40vh показан целиком, затем прогресс сбрасывается и растёт. SplitText режет заголовок на буквы, а детерминированный генератор случайных чисел задаёт каждой букве вектор разлёта. Анимация идёт по scrub, поэтому при скролле назад буквы собираются.

**Коллекция.** Индекс равен `Math.floor(progress * 4)`. Переход собран в один таймлайн: фон через `--collection-bg`, строки названия, распечатка старой модели, печать новой. Если индекс меняется во время перехода, таймлайн ускоряется в 3 раза, а промежуточные модели пропускаются. В конце функция `settle` принудительно выставляет итоговое состояние, поэтому быстрый скролл не оставляет следов.

**Каталог.** Сетка по мотивам демо Codrops «Grid to Full Preview» (github.com/gwen-bo/codrops-grid-to-preview, лицензия MIT). Код демо не копировался, эффект написан заново на React и GSAP. Пять колонок на компьютере, четыре на планшете, две на телефоне. При наведении карточка вместе с соседями в блоке 2×2 превращается в одно большое превью. Блок считает `catalogLayout.ts` по реальной сетке, поэтому он работает при любом числе колонок. Таймлайн: превью проявляется и чуть увеличивается, маска цвета фона в форме креста лежит ровно на зазорах между карточками и сжимается к центру, соседние карточки уходят к центру блока и гаснут, затем каскадом появляется карточка характеристик. В превью листаются фото товара и три ракурса его 3D-модели. Ракурсы рендерит `renderProductViews` в отдельном WebGL-контексте, когда каталог приближается к экрану, и только в свободное время браузера. Характеристики, цена и число крышек берутся из каталога, крышки считаются по весу из расчёта 2,5 г на крышку. На телефоне превью открывается касанием и так же складывается из четырёх карточек 2 × 2. Прокрутка его не закрывает: оно закрывается крестиком, коротким касанием вне превью или клавишей Escape. Касание считается коротким, если палец сдвинулся меньше чем на 10 px, поэтому свайп по странице не срабатывает как закрытие.

**Проблема.** Счётчики считаются от нуля при появлении. Частицы падают, ложатся кучей и поднимаются в силуэт стула.

**Процесс.** Лента сдвигается на `-(ширина ленты − 100vw)` по scrub. Зигзаг рисуется через `stroke-dashoffset`, а бегунок ставится по `getPointAtLength`. Все пять шагов устроены одинаково: текст слева, рамка `.frame` справа. На шагах 2–5 в рамке фото, на шаге 1 на том же белом фоне работает физика крышек.

**Физика крышек на шаге 1.** `src/three/process/capPile.ts` считает крышки как диски в плоскости рамки, без three.js и без Rapier, поэтому тяжёлый физический движок здесь не загружается. Метод: position-based dynamics с двумя подшагами и четырьмя проходами, поиск соседей через сетку, трение между крышками, отскок при сильном ударе. Покоящиеся крышки засыпают и не считаются, пока их не заденет быстрая соседка, поэтому шаг занимает около 0,2 мс. Цикл из трёх фаз: `pour` (крышки сыплются и скатываются по склону холма), `hold` (пауза), `drain` (дно раскрывается от центра, всё высыпается, цикл начинается заново). Стенки слегка нависают и у каждой крышки свой зазор до стенки: иначе диски выстраиваются ровными столбиками вдоль края. Палец и курсор внутри рамки раздвигают кучу. Глубина и наклон крышек только визуальные, из-за них куча выглядит объёмной. `capClip.glsl` обрезает крышки по скруглённой рамке через `gl_FragCoord`. Пока рамка за экраном, физика не считается. В reduced motion куча рассчитывается один раз и стоит неподвижно.

**Паспорт.** Стул превращается в табурет. На обеих моделях выбираются точки поверхности: на стуле они сортируются по высоте сверху вниз, на табурете снизу вверх, и точки соединяются в пары по порядку. Каждая крышка стартует в момент, когда линия отсечения стула доходит до её точки, проходит через сужение потока и садится на свою точку табурета. Поэтому стул тает, а табурет сначала собирается оболочкой из крышек и затем твердеет снизу вверх. Вся анимация считается только от прогресса скролла и обратима. Когда конфигуратор наезжает снизу, табурет остаётся на месте и закрывается им как обычная секция: материал печати отбрасывает всё, что ниже шва (`uClipFloor`).

**Расплав.** Шар расплавленного пластика, адаптация сцены с itsoffbrand.com. Секция стоит между «Философией» и «Почему LOOPFORM»: шар поднимается из-под конца «Философии», а «Преимущества» наезжают на него и закрывают ровно по шву `advantages-top`. Силуэт стула в «Проблеме» рассыпается в поток и уходит в рамку шага «Собираем»: точка втягивания частиц едет вместе с рамкой, а когда поток почти вошёл, куча в рамке начинается заново (`processDirective.refill`) и крышки сыплются сверху. До этого момента рамка ждёт и не засыпается сама (`processDirective.pouring`). Вершины смещаются шумом, нормали пересчитываются по соседним точкам. Цвет строится из искажённого шума и палитры бренда, а ступенчатая заливка даёт контуры, похожие на слои печати. Палец или курсор продавливают поверхность и разогревают её. Карточки летят из центра шара на камеру: глубина работает по-настоящему, поэтому они выходят сквозь поверхность. Заголовок лежит над холстом с `mix-blend-mode: difference`. Шар режется в шейдере по границам секции, поэтому следующая секция закрывает его ровно по шву.

**Конфигуратор.** Секция закреплена и занимает один экран. На компьютере все настройки видны в панели. На телефоне и на низких экранах панель становится вкладками, а строка углов всегда видна под моделью. Доступны 10 моделей: при смене старая распечатывается, новая печатается. У каждой модели свои вариации, они описаны данными в `ru.configurator.models[].variants`: высота и подушка у TOLQYN, форма и сидушка у TAS, сидушка у BIIK, подушка у QUM, столешница у KOL, свет у SAULE, размер у JAPYRAQ, проём у SAIABAQ, раскрытие у ORNEK, число модулей и поворот у UYA. Вариации с флагом `rebuild` меняют геометрию: модель распечатывается и печатается заново, а `modelLibrary` кеширует каждую форму по ключу `shapeKey`. Остальные применяются на лету: высота через `uLegStretch`, подушка показом меша, столешница сменой материала, свет через `uGlow`, размер кашпо масштабом. Цена и вес берутся из варианта, если в каталоге есть данные, иначе остаются каталожными. Ссылка в Telegram содержит все выбранные варианты. На телефоне все 10 моделей видны сеткой 5 × 2. Актёр плавно применяет выбор: цвет через `uBaseColor`, высоту через `uLegStretch`, фактуру через `uRelief`.

Жесты живут в `useViewGestures.ts`. Один палец вращает модель по двум осям, два пальца двигают и масштабируют. Мышью: перетаскивание вращает, Shift или правая кнопка двигают. Двойное касание и кнопка сбрасывают вид. На якоре стоит `touch-action: none`, поэтому страница листается свайпом по панели, а не по модели. Значения лежат в мутируемом `configuratorView`, чтобы движение пальца не перерисовывало React. `DrumNumber` прокручивает каждую цифру как ленту 0–9. Ссылка Telegram содержит параметры в base64url.

**Манифест.** Строки движутся навстречу друг другу по scrub. Фото собрано из 10 полос. Каждая полоса показывает свой кусок снимка с кадрированием как у `cover`, а раскрывается через `clip-path`, поэтому снимок не искажается.

**Философия, Преимущества, Конкуренция.** Текстовые секции без 3D. Карточки и строки таблицы появляются каскадом. Заголовки здесь намеренно без `SplitText`: разбивка на строки заметно удлиняла старт страницы. «Философия» наезжает на манифест, остальные идут обычным потоком.

**Для бизнеса.** Карточки лежат стопкой и раскладываются в ряд через Flip.

**Рынок.** Числа считаются от нуля, линия дорожной карты рисуется по скроллу.

**Футер.** Логотип печатается полосами. Физика работает на Rapier: каждая буква это статичный бокс, размер которого снят через `Range.getBoundingClientRect()`. Логика считается в системе координат логотипа, а при отрисовке к телам прибавляется текущее положение логотипа на экране. Поэтому физика не зависит от скролла.

**Шапка.** Триггеры на каждой секции меняют тему. На Cap Red текст становится чёрным: и Bone, и Graphite не дают там контраст AA.

## Режим презентации

`animation/presentation.ts` строит список кадров из тех же ключевых точек, что и анимации. Кадры читаются из DOM в момент нажатия, поэтому список верен на любом экране. Во время перехода одно следующее нажатие ставится в очередь.

## Адаптив и reduced motion

Телефон и компьютер используют одну и ту же хореографию: те же секции, те же закреплённые сцены, те же переходы и частицы. Различается только вёрстка в SCSS.

Меньше 768 px:

- коллекция: название внизу, модель над ним, миниатюры и мини-карточка в нижней панели;
- процесс: та же горизонтальная лента, но внутри панели текст стоит над иллюстрацией;
- паспорт: 3D занимает верхнюю часть экрана, текст нижнюю, а описание раскрывается только у активного пункта;
- каталог: кнопки листают по одной карточке;
- для бизнеса: карточки выезжают из стопки без изменения высоты страницы, потому что они стоят в столбец;
- частиц меньше, камера не реагирует на курсор, у лампы отключён дорогой `transmission`.

Отдельная ветка осталась только для `prefers-reduced-motion`: Lenis не создаётся, sticky отключается в CSS, разлёт букв не запускается, модели сразу напечатаны, частицы статичны. Её обслуживает функция `updateStatic` в `choreography.ts`: актёр просто стоит у своего видимого якоря.

Холст на телефоне имеет высоту `100lvh`, поэтому не меняет размер, когда прячется адресная строка браузера.

## Шрифты

Шрифты лежат локально в пяти файлах по 27–76 КБ. Готовые сабсеты Google и fontsource не содержат `≈`, `←` и `→`, поэтому файлы собраны из полных шрифтов через fontTools. Размер Inter зафиксирован на оптическом значении 14. Все шрифты остались вариативными по весу.

В JetBrains Mono нет символа `₸`, поэтому цены набираются Unbounded или Inter. Для отсутствующих символов в стеке стоит Inter. В Unbounded нет казахских букв: это важно, если появится версия на казахском.

## Как заменить модели и фото

**Модели.** Положите файлы в `public/models`:

- `tolqyn.glb`, `tas.glb`, `qum.glb`, `saule.glb`;
- `cap.glb` для крышек.

Они подхватятся автоматически, код менять не нужно. `ProductModel` центрирует модель, ставит основание на y = 0 и подгоняет высоту под размер процедурной версии. Материал печати применяется сам, поэтому текстуры не нужны. Поддерживается сжатие Draco.

**Фото манифеста.** Файл `public/images/manifesto.webp` подключён. Без него показывается градиент. Кадрирование задаёт `--photo-focus` в `Manifesto.module.scss`: 0 это верх снимка, 1 это низ.

**Фото товаров.** Подключены девять моделей, кроме BIIK: у него нет снимка, поэтому каталог показывает рендер 3D-модели. Чтобы добавить новое фото, положите JPG в `public/images`, допишите его в `SOURCES` в `scripts/prepare_images.py`, запустите `python scripts/prepare_images.py` и добавьте строку в `src/content/images.ts`. Скрипт приводит кремовые снимки к белому фону, не меняя цвет изделия, и заново собирает широкий кадр манифеста.

**Фото процесса.** Поле `photo` у шага в `ru.ts` заменяет 3D-иллюстрацию большим снимком, поле `inset` добавляет маленький снимок под текстом и оставляет 3D. Шаги 2 и 3 используют `photo`, шаги 4 и 5 используют `inset`, потому что там живут анимированная печать и QR-бирка. Если убрать `photo`, 3D-иллюстрация вернётся сама.

Рабочие файлы лежат в WebP. Исходники Gemini в `public/images` сайтом не используются и попадают в сборку только как лишний вес, поэтому перед деплоем их можно убрать из этой папки.

## Производительность

- Один холст, один цикл обновления инстансов.
- Модуль физики весит около 2,2 МБ из-за встроенного wasm и загружается только у футера.
- Второстепенные актёры создаются после прелоадера, миниатюры рендерятся в простое браузера.
- Шейдер печати компилируется один раз: у всех актёров общий ключ программы.
- Отрисовка засыпает между рынком и CTA, где 3D нет.
- `chunkSizeWarningLimit` поднят из-за ленивого модуля физики.

Тень под моделью сделана текстурой, а не `ContactShadows`. Причина в том, что `ContactShadows` рисует сцену переопределённым материалом, не знает про отсечение и показал бы тень целого стула на любом этапе печати.
